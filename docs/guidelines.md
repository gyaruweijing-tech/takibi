# guidelines — 開発ルールと完成の条件

最終更新: 2026-10-08

## 進め方

1. 作業ごとに `.steering/日付-作業名/` を作り、requirements → design → tasklist の順に書く。1枚ごとに本人の OK をもらう
2. requirements の完成条件は [product.md](product.md) のゴール（G1〜G4）から引く。書き方は **数値／参考画像／本人が触ってOK** のどれか
3. requirements に必ず「**変えてはいけないもの**」を書く（例：上から落とす感じ・燃え移りの速さ・決めた色）
4. 小さい直しはまとめて1つの作業にする
5. 見た目が分からないものは、捨てる前提の試作で確かめてから本番に入れる

## 書き方

- 単位は SI（m・kg・秒・℃）。大きさは実物の寸法で書き、倍率で見せ方をごまかさない（[experience.md](experience.md) の「大きさの決まり」）
- 数値には、なぜその値にしたかと日付をコメントで残す（types.js の書き方に合わせる）
- 燃焼（js/burn/）に見た目のコードを入れない

## 確かめ方（3段）

1. **自動**：`node tools/sim.mjs`・`node tools/sustain.mjs`（燃え方の秒数）、`?bench`（重さ）、ブラウザで操作して数える（落ちた数・カーソルとのずれ）
2. **別の AI のレビュー**：変えてはいけないものが壊れていないか。指摘はうのみにせず、コードで確かめてから採否を決める（手順は開発手法の REVIEW.md。このリポジトリの外）
3. **本人**：触って OK。見た目は正解集と並べたスクショで見てもらう

直す前と直した後の両方を測って、PROGRESS に数値を残す。

## 完成の条件（毎回これを満たしたら終わり）

- [ ] requirements の完成条件を全部満たした（証拠：数値・スクショ・本人の OK）
- [ ] 変えてはいけないものが変わっていない
- [ ] 本人の PC で 60fps を切っていない（`?bench`）
- [ ] 「落ち着きを壊すもの」（product.md）を足していない
- [ ] docs/ と README を、変わった内容に合わせて直した
- [ ] PROGRESS.md に「やったこと・前後の数値・次」を書いた
- [ ] 遊んでもらうときは、サーバーを立ち上げてから URL を渡した

## 公開前提

- このリポジトリは公開される。docs にも個人的なことは書かない
- 元の動画・正解集の写真（reference/）は入れない。ネットの写真はライセンスを確かめて CREDITS.md に書く
